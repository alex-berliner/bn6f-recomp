| Workflow | Burr UI project | What it is for |
|---|---|---|
| [verify](verify.md) | recomp-verify | Verify the main checkout (docs/PROCESS.md §3): lift and build, difftest the changed functions against their lifted originals on random inputs and on the original game's captured calls, run them on the CPU oracle, replay every recorded route in lockstep, and the battle sweep when battle code changed. |
| [capture](capture.md) | recomp-capture | Capture the original game's own calls of some functions (the inputs that difftest and the CPU oracle check conversions on): pick a recorded route that executes them, replay it on the original, save the first calls of each. (docs/PROCESS.md §4: "capture 40 calls each on a route that runs them".) |
| [farm](farm.md) | recomp-farm | Outside models convert small lifted functions (docs/PROCESS.md §4, "By outside models"). One `farm` run is one function and one model: the model writes readable C, the farm's acceptance test checks it against the lifted original on the captured calls and random inputs, failures go back to the model for repair. A `farm batch` run builds the host difftest once, skips pairs that are already finished, and runs the rest as its child runs. |
| [farm-batch](farm-batch.md) | recomp-farm | Outside models convert small lifted functions (docs/PROCESS.md §4, "By outside models"). | [convert](convert.md) | recomp-convert | Claude converts a subsystem (callers and callees together) to readable C (docs/PROCESS.md §4, "By Claude"): capture the original's calls of the functions, wait for Claude to write cport/src/game/*.c, verify (a child verify run), and either go back to Claude with the report or commit. Afterwards the record workflow puts the findings into the symbol database. |
