# Skeptical audit: the names only MiniMax-M3 proposed AND checked (2026-10-20/21)

Audit of every name that landed since 2026-10-20 23:00 whose **proposer and cross-checker were both `minimax/MiniMax-M3`** — the self-approved case. Nothing here changed a symbol or a database entry; this is output only.

- **What was audited:** 288 names — 197 functions (`wf investigate` runs 20261021-003336, -004112, -004802, -005336, -023329, -023934, -024121, -024706, -025128) and 91 data labels (`wf investigate-data` runs 20261020-194825, -223307).
- **Reviewer:** `minimax/MiniMax-M3` via `tools/llm.py complete` (timeout 180, retries 3). A **skeptical** prompt, never the proposer's: "You are auditing the name X … Quote the line that decides it … Verdict: keep | too-specific | too-generic | wrong | cannot-tell".
- **Evidence per name:** the CURRENT assembly (`python3 tools/asmcat.py ADDRESS`) plus, for a function, the call sites that reach it and its graph neighbours (`tools/funcindex.py call_neighbours build-abi/graph.json`); for a data label, its definition and every reading/writing site in `bn6f/asm` and the data sections (`bn6f/*.s`, `bn6f/data/*.s`).
- **Per name:** 3 independent samples. A name is **`doubtful`** when ANY sample says `wrong` or `too-specific` AND the line it quotes really exists in the assembly (checked with grep; quotes that are not found are rejected).

## 5. Honest reading of the numbers

- The reviewer is a **good flagger of outright-wrong names** (9/10) but a **weak discriminator at the keep/too-specific boundary**: it also calls 14/20 = 70.0% of the legitimate Hyper-checked baseline names doubtful.
- The MiniMax-only set is flagged at 82.6% — barely distinguishable from the 70.0% baseline. So "doubtful" here is **not** evidence that the MiniMax-only names are worse than the Hyper-checked ones; it mostly reflects that this reviewer treats a claim about behaviour as "too-specific" unless the code shows it outright.
- The one deliberate miss (`getAiAttackDuration` on a 26-byte function) landed on `cannot-tell` twice: with so little code the reviewer judged the evidence insufficient rather than wrong.
- **Most common objection is `too-specific`**, i.e. the name promises more (a type, a count, a single responsibility) than the shown code demonstrates — the expected failure mode of a model naming from call sites alone. Example: `rfuLinkStateChangeFlag` is defined with `.space 40` (40 bytes) yet the name and summary call it a one-byte flag.

## 6. Method notes / caveats

- **Temperature:** `tools/llm.py complete` builds the request body with no `temperature` field, so the task's "3 samples at temperature > 0" could not be requested explicitly. We ran 3 samples per name at the provider default (which still varies run to run — the same wrong set scored 10/10 on one repeat run and 9/10 here), so treat per-name verdicts as noisy and the rates as ±a few points.
- **Which names count as "both MiniMax":** the per-entry `evidence.result` line ("proposed by …; cross-checked by …") is written by `tools/wf/wf/tools/investigate*.py` from the run's actual models and is authoritative. Note the **commit subjects are not**: `tools/investigate_data_land.py` hardcodes "(proposed by MiniMax M3, checked by MiniMax M3)" into every data-label commit, and two function commits (`investigate-20261021-003336`, `-004112`) carry a stale "Hyper glm-5.3-flash" subject despite MiniMax-proposed entries. We therefore keyed on the entry evidence, not the subject.
- The 20 data labels from run `investigate-data-20261020-192515` (commit `807ae57a`, subject "Hyper glm-5.3-flash, checked by MiniMax M3") are **excluded** here: their subject claims Hyper proposed them. (Their entry evidence says MiniMax — that subject/evidence conflict is itself worth a look, but the task enumerated only the 1948/2233/2304 runs.)
- `investigate-data-20261020-230424` (the task's "2304…" run) was **never landed** (no land_message/land_record in its run dir), so it contributes nothing.
- Quote verification greps the exact packet shown to the reviewer; `===`/`---` section headers and our own `#note:` diagnostic lines are excluded so a reviewer cannot pass them off as code. This caught and removed 8 false-positive "quotes" on a first pass.
- No symbol, entry, or commit was modified. Outputs only: this file and `name_audit.tsv`.
