# Secondary entries of lifted functions

A secondary entry is a code address in the middle of a function that other code may reach: a global `name::` label on an instruction (in bn6f/asm and bn6f/data). `tools/lifter/analysis.py` now turns every such label into a data-reference entry (`info.global_labels`, read from the `::` labels of bn6f/**/*.s). The lifter then emits it as an extra case of its unit's `U_xxxxxxxx(entry)` switch and `dispatch_table.c` maps its address to a function. Before, only labels that an aligned data word pointed at, a call or tail call named, or a function symbol covered were entries.

Total `::` code labels inside functions: 663. Already dispatchable before: 0. Newly dispatchable: 663.

Not handled on purpose: pointers packed unaligned into script bytes that name a label which is not `::`. A byte scan of the ROM finds thousands of chance matches inside compressed data (for example `locret_808FF26` as a byte pattern 267 times in cutscene scripts), so it cannot be used as an entry source. Such a target needs a `::` label or an entry in tools/lifter/.

Readable C (cport/src/game): no function there contains one of these labels. The lifter refuses an override that lacks an entry of its unit (`must define all its entries`), and the run passes.

Referenced by: ROM words naming the address (with or without the Thumb bit, any alignment), shown as symbol+offset of the word, and the number of uses of the name in the sources (the label line itself excluded).
